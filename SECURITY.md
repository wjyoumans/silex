# Security Policy

## Supported versions

Security fixes are considered on a best-effort basis for the latest published
Silex release only. Earlier releases, untagged snapshots, optional development
backends, and unsupported configurations do not receive security updates.

Silex is an early research-oriented 0.x library. There is no guaranteed
response time, remediation schedule, service-level agreement, or production
support commitment.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability. Use
[GitHub private vulnerability reporting](https://github.com/wjyoumans/silex/security/advisories/new)
or email William Youmans at [youmans.wj@gmail.com](mailto:youmans.wj@gmail.com).
If private vulnerability reporting is unavailable, use email.

Include, when possible:

- the affected Silex version or commit;
- the affected configuration and dependency versions;
- reproduction steps or a minimal proof of concept;
- the expected security impact; and
- any suggested mitigation.

Do not include secrets or third-party personal data that are unnecessary to
reproduce the problem. Reports and coordinated disclosure are handled on a
best-effort basis, with reporter privacy respected as far as practicable.

Ordinary correctness defects without a security impact may be reported through
the [public bug form](https://github.com/wjyoumans/silex/issues/new?template=bug.yml).
