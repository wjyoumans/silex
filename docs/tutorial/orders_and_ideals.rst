Orders and Ideals
=================

This tutorial moves from a number field to orders, integral ideals,
fractional ideals, and local algebra.  The corresponding compiled examples
are :download:`field_order_ideal_basics.cpp <../../examples/field_order_ideal_basics.cpp>`
and :download:`local_relation_basics.cpp <../../examples/local_relation_basics.cpp>`.
The focused fragments below emphasize API contracts; the complete compiled
field/order/ideal example is included at the end.

Build Orders From Field Handles
-------------------------------

Use order factories for ordinary public code:

.. code-block:: cpp

   namespace sflint = silex::flint;

   sflint::Fmpz d;
   sflint::fmpz_set_si(sflint::FmpzRef(d), 2);

   silex::NumberField K =
           silex::NumberField::quadratic(sflint::FmpzConstRef(d));
   if (!K.is_defined()) {
       return false;
   }

   silex::Order O = silex::Order::equation_order(K);
   if (!O.is_defined()) {
       return false;
   }

``Order`` stores its ``NumberField`` parent by value and is itself a
value-like handle to shared order data.  Returned objects such as
``OrderElement``, ``Ideal``, ``FractionalIdeal``, ``PrimeIdeal``, and
``FactorBase`` keep their parent order alive where needed.

Use The Right Element Type
--------------------------

Integral ideals are generated by ``OrderElement`` values because they live in
the order lattice.  Fractional principal ideals are generated by ambient
``Element`` values because denominator clearing belongs to the
``FractionalIdeal`` representation:

.. code-block:: cpp

   silex::Element theta_K(K);
   if (!theta_K.gen()) {
       return false;
   }

   silex::OrderElement theta_O(O);
   if (!theta_O.set_element(theta_K)) {
       return false;
   }

   silex::Ideal I(O);
   if (!I.set_principal(theta_O)) {
       return false;
   }

   silex::FractionalIdeal J(O);
   if (!J.set_principal(theta_K)) {
       return false;
   }

Check each boolean return value before reading outputs.  Failure-preserving
methods leave documented outputs unchanged when inputs are invalid, parents
are incompatible, or a certification step cannot be completed.

Local Algebra And Relations
---------------------------

For prime decomposition, factor bases, relation rows, and residue-field
arithmetic, use the local algebra layer:

- ``PrimeIdealList`` for prime ideals above a rational prime;
- ``FactorBase`` for copied prime ideals grouped by rational-prime blocks;
- ``IdealFactorization`` for factor-over-base exponent rows;
- ``Relation`` and ``RelationMatrix`` for principal-generator relation rows;
- ``ResidueRing`` and ``ResidueField`` for finite quotient arithmetic.

These objects use parent handles instead of long-lived raw parent pointers.
Borrowed accessors such as ``parent()`` are local views, not identity tokens.
Use semantic parent compatibility helpers and status returns.
